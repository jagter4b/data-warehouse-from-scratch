# BI_AI Assistant

> An AI-powered Business Intelligence assistant that connects to Microsoft SQL Server, understands your database schema automatically, and answers business questions in natural language.

---

## Features

| Feature | Details |
|---|---|
| 🧠 AI SQL Generation | GPT-4o converts natural language → T-SQL |
| 🔒 SQL Safety Layer | Blocks all write/DDL operations |
| 📐 Auto Schema Discovery | Tables, views, columns, PKs, FKs |
| 📊 Smart Visualisation | Auto-detects bar / line / pie / KPI charts |
| 💬 Chat Interface | Full conversation history with context |
| 🛠 SQL Workshop | Edit, validate, re-run and explain queries |
| 📤 Export | Download results as CSV or Excel |
| 🌑 Dark UI | Glassmorphism theme with purple/cyan accents |

## Quick Start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

> **Prerequisite**: [ODBC Driver 17 for SQL Server](https://learn.microsoft.com/en-us/sql/connect/odbc/download-odbc-driver-for-sql-server) must be installed.

### 2. Configure environment

The app reads your OpenAI key from the **project-root `.env`** automatically.
Your root `.env` already contains `OpenAI_API=...` — the app handles both key names.

To override locally, copy `.env.example` → `.env` inside this folder:

```bash
copy .env.example .env
# then edit .env
```

### 3. Run

```bash
streamlit run app.py
```

## Security & Guardrails

The application implements a multi-layered security validation pipeline in [`security.py`](./security.py) that inspects every SQL query generated by the AI before it is ever sent to the Microsoft SQL Server database. This makes the system 100% resilient against malicious queries (like SQL Injection or prompt-hacking attempts to drop tables).

### How safety is enforced:
1. **Query Whitelist (First Token Check)**: Every query must start exclusively with **`SELECT`** or **`WITH`**. Any query starting with destructive commands like `DROP`, `DELETE`, `TRUNCATE`, or `ALTER` is instantly blocked.
2. **Semicolon Blocker**: Multiple SQL statements separated by semicolons (`;`) are rejected to prevent query-chaining attacks.
3. **Keyword Blocklist Scanner**: The query is scanned using regex word-boundary matching for blocked keywords (case-insensitive):
   * `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`
   * `CREATE`, `EXEC`, `EXECUTE`, `MERGE`
   * `GRANT`, `REVOKE`, `BULK`, `OPENROWSET`, `OPENQUERY`
   * `RESTORE`, `BACKUP`, `SHUTDOWN`, `KILL`, `WAITFOR`, `XP_`, `SP_`
4. **Least-Privilege Database Connection (Defense in Depth)**: We recommend connecting to the database using an account with read-only permissions (`db_datareader`). Even if both the AI and code-level validators fail, the database permissions will physically block any modifications or drops.

### Example: What happens if I type "drop database"?
1. The AI model's system prompt strictly prohibits generating anything other than `SELECT` statements.
2. If the AI is bypassed (prompt injection) and generates a query like `DROP DATABASE BI_AI`, the application runs it through `security.py`.
3. The query is rejected immediately because its first word is `DROP` (violating rule 1) and contains a blocked word `DROP` (violating rule 3).
4. The user is displayed a safe error badge and no execution is sent to the SQL Server.

## Authentication

| Mode | How |
|---|---|
| Windows Auth | Leave username/password blank, select *Windows Authentication* |
| SQL Auth | Select *SQL Server Authentication*, enter credentials |

The form pre-fills from your `.env` values (`DEST_DB_HOST`, `DEST_DB_NAME`, `DEST_DB_TRUSTED_CONNECTION`).
